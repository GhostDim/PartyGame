# ROADMAP проекта PartyBox

## Этап 1: Архитектурное ядро, Лобби и Выбор игр
- [ ] **1.1. Базовый сервер и менеджер комнат (Node.js + Socket.io)**
  - Express-сервер (порт 3000, локальная раздача статики из `/public`).
  - Хранилище состояния в оперативной памяти (`GameStateManager`): список игроков, голоса за игры, статус раунда, режим ТВ (on/off).
  - Пароль администратора (задается в конфиге сервера, например `admin123`).
- [ ] **1.2. Защищенный интерфейс Администратора (`public/admin.html`)**
  - Экран ввода пароля администратора -> проверка на сервере и выдача admin-токена в `localStorage`.
  - Панель управления:
    * Живой список подключенных игроков и их статусы. 
    * Переключатель режима "С экраном ТВ / Без ТВ".
    * Мониторинг голосования за игры и выпадающий список для принудительного выбора игры.
    * Кнопка старта раунда ("Начать игру").
    * Кнопка безопасного выключения системы (`Safe Shutdown`).
- [ ] **1.3. Клиент игрока (`public/index.html`)**
  - Экран ввода никнейма и выбора аватара.
  - Экран ожидания со списком игр для голосования (живые счетчики голосов).
  - Блокировка действий до команды старта от администратора.
- [ ] **1.4. Пассивный экран ТВ (`public/tv.html`)**
  - Вход без регистрации: показ подключенных гостей, анимация ожидания, шкала голосов за игры.

## Этап 2: Первая игра — «ТВ-Викторина» (Party Quiz)
- [ ] **2.1. Модуль игры и парсер вопросов**
  - Структура JSON-файла для базы вопросов (вопрос, 4 варианта, правильный ответ, время).
  - Стейт-машина викторины: `LOBBY` -> `QUESTION_PREVIEW` -> `ANSWERING` -> `ROUND_RESULTS` -> `GAME_OVER`.
- [ ] **2.2. Синхронизация экранов викторины**
  - Экран ТВ: отображение вопроса, цветных блоков с вариантами ответов и наглядного таймера.
  - Экран игрока: смена интерфейса лобби на 4 цветные кнопки ответов (с виброоткликом `navigator.vibrate`).
  - Начисление очков с учетом скорости ответа.
- [ ] **2.3. Табло победителей и завершение игры**
  - Финальный подиум на ТВ.
  - Возврат всех игроков обратно в главное меню голосования за игры с сохранением очков.

## Этап 3: Вторая игра — «Аукцион пальцев» (Finger Auction)
- [ ] **3.1. Логика риск-механики**
  - Механика удержания пальца на экране смартфона (`touchstart` / `touchend`).
  - Серверный рандомайзер времени взрыва (от 4 до 15 сек).
  - Расчет растущего банка очков.
- [ ] **3.2. Синхронизация и визуал**
  - Нарастающий визуальный таймер и звуковые сигналы.
  - Определение победителя раунда (отпустил последним *до* взрыва).

## Этап 4: Панель администратора и системная интеграция
- [ ] **4.1. Централизованное управление сессией**
  - Админ видит каталог установленных игр, может ставить раунд на паузу или пропускать шаги.
  - Автоматическое переключение интерфейсов всех подключенных экранов при смене игры.
- [ ] **4.2. Системные функции Pi**
  - Кнопка «Выключить консоль» (`Safe Shutdown`) в панели `/admin` через безопасный вызов `sudo poweroff`.

## Этап 5: Автономность (Перенос консоли в «полевой» режим)
- [ ] **5.1. Настройка автономной точки доступа Wi-Fi (Hotspot)**
  - Настройка платы как Wi-Fi роутера (SSID: `PartyBox`).
  - Настройка DNS/Captive Portal (автоматическое открытие страницы при подключении смартфона к Wi-Fi).
- [ ] **5.2. Автозапуск через Systemd**
  - Создание системной службы для старта сервера при подаче питания.
- [ ] **5.3. Перевод накопителя в Read-Only (OverlayFS)**
  - Аппаратная защита microSD от повреждения при внезапном обесточивании.
